# Relay MCP

Generated by `python -m relay_core.mcp_tools`. Do not edit by hand.

Endpoint: `POST /api/method/relay_core.mcp.endpoint` with `Authorization: token <api key>:<api secret>` of a user with a Relay role. JSON-RPC 2.0, protocol 2025-06-18, tools and resources. Browser requests (an `Origin` header) and cookie sessions are refused. Requests are at most 1 MB; `templates_media_upload` may send up to 7 MB.

Safety classes: **R** read, **W** internal write, **S** customer send or live change.

The older `relay.*` tool names still work but are not listed.

## Guide

## Domain model
- **Contact** (`RELAY-CON-##########`): one person or group you talk to. It has **endpoints** (a phone number, Telegram chat or email address) and the Frappe Contact behind it.
- **Channel** (`RELAY-CH-##########`): one WhatsApp number, Telegram bot or mailbox. `channels_list` gives them.
- **Message** (`RELAY-MSG-##########`): one incoming or outgoing message in a chat.
- **Chat**: all messages of one Contact. `inbox_list` lists chats; `messages_list` reads one.
- **Business record**: an ERP document (for example a Customer) that a Contact is linked to. `records_types`, `records_list` and `records_messages` show the record tiles.
- **Ticket** (`TKT-#####`): a support case made from messages.
- **Template**: a WhatsApp message approved by Meta. Only templates can start a chat or reach a person after 24 hours.
- **Campaign**: one template or message sent to many numbers, with live counts.

## Rules
- **24-hour window**: on WhatsApp you can send free text or media only within 24 hours of the customer's last message. After that the send fails with "Outside the 24-hour reply window"; send an approved template with `chat_send_template` instead. `messages_read_one` shows if the window is open.
- **Customer sends** (class S) reach a real person or change live state. Every one needs `request_key`. A repeated key returns the first result and sends nothing new. Use a new key only for a new message.
- **Confirm**: campaign start, schedule, resume and retry, template delete and flow publish need `confirm: true`. Campaign start and schedule also need `expected_recipients` equal to the count from `campaigns_validate`.
- **Permissions**: you act as the API key's user. A chat, record or campaign the user cannot see returns "Not found" or "Not permitted". Campaigns, contacts_create and flows need the Relay Communication Manager role.
- **Templates** go to Meta for review the moment you create or update them; there is no local draft. Status starts as PENDING; read it again with `templates_list`.

- **Several actors**: staff in the portal, the Relay automation and AI, and other MCP agents can work on the same chats. Each MCP agent is its own Frappe user. Replies show `sent_by` and `via` (`mcp`, `automation`, `staff` or `system`).
- **Read state is yours**: `chat_mark_read` changes only your user's unread count. It sends no read receipt and hides nothing from staff or other agents.
- **Claims**: `chat_claim` holds a chat for up to 30 minutes. Other MCP agents then get "Chat claimed by X until T" on every send to it, and the Relay automation and AI stop replying (when your user has the Relay Communication Manager role). `chat_release`, or the end of the claim, resumes them. Staff in the portal can still reply.
- **Reply guard**: pass `after_message` (the newest message you read) on every send. When a newer message or send exists, the send is refused with "Chat changed: ..."; read the chat again before you answer. A repeat with the request_key of your own earlier send skips the guard and returns the first result.

## Workflows
**Safe polling loop (several agents)**
1. `changes_since` with your saved cursor. Save the new cursor at once. The first call, without a cursor, gives the current cursor.
2. For each chat with an `inbound` event that you will answer: `chat_claim` (skip the chat if it is claimed by another agent).
3. `messages_list` or `messages_read_one` to read the chat and the reply window.
4. `chat_send_text` (or `chat_send_template`) with a new request_key and `after_message` set to the newest message you read. On "Chat changed", go back to step 3.
5. `chat_mark_read`, then `chat_release`.

**Reply to unread messages**
1. `messages_list_unread` to see unread incoming messages by chat.
2. `messages_read_one` for one message with context and the reply window state.
3. `chat_send_text` with that message id, your text, a new request_key and `after_message` (or `chat_send_template` when the window is closed).
4. `send_status` with the returned message id to follow delivery.
5. `chat_mark_read` to clear the chat's unread count for the user.

**Create a template**
1. `templates_media_upload` when the header has an image, video or document; keep the returned handle.
2. `templates_create` with name, language, category and components; it is submitted to Meta at once.
3. `templates_list` about a minute later (after the next sync) to see PENDING, APPROVED or REJECTED with the reason.

**Run a campaign**
1. `campaigns_create` with a title, an approved template (or a message) and rows of phone numbers and values. It never sends.
2. `campaigns_validate` for the sendable recipient count, skipped rows and issues. Show this to the user.
3. `campaigns_control` with action start, `confirm: true` and `expected_recipients` from step 2.
4. `campaigns_read` to follow the counts; pause, resume or cancel with `campaigns_control`.
5. `campaigns_retry_failed` with `confirm: true` once a completed campaign has failed rows.

## Tools

### `account_overview` (R)

Read the last 7 days of message activity and the current unread queue counts.

- **Use when:** the user asks how busy the inbox is or wants a daily summary.
- **Do not use when:** you need the messages themselves; use messages_list_unread.
- **Returns:** {activity: daily incoming and outgoing counts, queues: unread and open counts}.
- **Common errors:** "Not permitted" without a Relay role.
- **Arguments:** none

### `activity_log` (R)

Read the audit log of MCP writes and sends: which agent did what, in which chat, and the reply time.

- **Use when:** the user asks who answered, how fast, or what an agent did.
- **Do not use when:** you need who sent one message; messages_list shows sent_by and via on each reply.
- **Returns:** {items: [{creation, user, tool, contact, action, client, request_key, message, response_seconds}]}. Managers see every agent; other users see their own rows.
- **Common errors:** "Not permitted" for another user's rows without the manager role.
- **Arguments:** `user`?, `contact`?, `limit`?

### `campaigns_append` (W)

Add up to 5000 more rows to a Draft campaign made with campaigns_create.

- **Use when:** the audience has more than 5000 rows.
- **Do not use when:** the campaign is not Draft.
- **Returns:** the campaign as campaigns_read returns it.
- **Common errors:** "Campaign is Running"; "A campaign supports at most <n> rows".
- **Arguments:** `name`, `rows`

### `campaigns_control` (S)

Start, schedule, unschedule, pause, resume or cancel a campaign. Start and schedule send to real people.

- **Use when:** the user agreed to the count from campaigns_validate. start/schedule need confirm: true and expected_recipients; resume needs confirm: true.
- **Do not use when:** you have not run campaigns_validate just before.
- **Returns:** the campaign as campaigns_read returns it.
- **Common errors:** "Recipient count changed" when expected_recipients differs; "Campaign is <status>" for a wrong transition; "Validate recipients before sending".
- **Arguments:** `name`, `action`, `scheduled_at`?, `confirm`?, `expected_recipients`?

### `campaigns_create` (W)

Create a Draft campaign from up to 5000 rows with an approved template (or a text/media message). It never sends.

- **Use when:** the user wants to message many numbers.
- **Do not use when:** you message one person; use chat_send_template.
- **Returns:** the campaign as campaigns_read returns it, status Draft. Its name is the title. Counts fill in a moment later; use campaigns_validate for the recipient count.
- **Common errors:** "A campaign with this title already exists"; "Template is not approved"; mapping problems name the column.
- **Arguments:** `title`, `channel`, `rows`, `template_name`?, `language`?, `message`?, `mapping`?, `reply_window_hours`?

### `campaigns_list` (R)

List campaigns with status and counts, 30 per page. Communication managers only.

- **Use when:** finding a campaign by title or status.
- **Do not use when:** you know the campaign name; use campaigns_read.
- **Returns:** {items: [{name, title, status, template_name, total_count, sent_count, replied_count}], next}.
- **Common errors:** "Not permitted" for users without the manager role.
- **Arguments:** `query`?, `after`?, `status`?

### `campaigns_read` (R)

Read one campaign's status, counts, issues and a page of 50 recipients.

- **Use when:** following a running campaign or checking its results.
- **Do not use when:** you are about to start it; use campaigns_validate.
- **Returns:** {name, status, counts: {total, skipped, queued, sent, delivered, read, failed, replied}, issues, recipients, next}.
- **Common errors:** "Not found" for an unknown name; "This is not a WhatsApp bulk campaign".
- **Arguments:** `name`, `after`?, `status`?

### `campaigns_retry_failed` (S)

Send the failed rows of a Completed campaign again. A repeat call changes nothing.

- **Use when:** campaigns_read shows failed rows and the user wants them sent again.
- **Do not use when:** the campaign is still running.
- **Returns:** the campaign as campaigns_read returns it.
- **Common errors:** "arguments.confirm must be true".
- **Arguments:** `name`, `confirm`

### `campaigns_validate` (R)

Check a campaign before sending: how many recipients will be sent, skipped rows and their reasons, and for text or media how many numbers are inside the 24-hour window.

- **Use when:** always right before campaigns_control start; show the result to the user.
- **Do not use when:** the campaign is already running; use campaigns_read.
- **Returns:** {name, status, ready, recipients (pass as expected_recipients), skipped, issues, error_rows, window}.
- **Common errors:** "Not found"; "Not permitted" for non-managers.
- **Arguments:** `name`

### `changes_since` (R)

Read what happened in all your chats after your own cursor: new incoming messages and replies by anyone (staff, Relay automation and AI, other MCP agents), plus the active claims.

- **Use when:** at the start of every poll. Keep the returned cursor and pass it next time; without a cursor you get the current cursor and no events.
- **Do not use when:** you need a full chat history; use messages_list.
- **Returns:** {events: [{type: inbound|reply, name, contact, content, status, creation, sent_by, via, client}], cursor, has_more, claims: [{contact, claimed_by, until}]}. Delivery status changes of older messages are not events; use send_status.
- **Common errors:** "Not permitted" without a Relay role.
- **Arguments:** `cursor`?, `limit`?

### `channels_list` (R)

- **Use when:** a send, template or campaign needs a channel name (RELAY-CH-...).
- **Do not use when:** you need contacts or chats; use contacts_search or inbox_list.
- **Returns:** {items: [{name, channel, enabled, label, address, is_default}]}.
- **Common errors:** "Not permitted" when the user has no Relay role.
- **Arguments:** none

### `chat_send_other` (S)

### `chat_send_template` (S)

### `templates_create` (S)

Create a WhatsApp template on the channel's WhatsApp Business Account. It is submitted to Meta for review at once.

- **Use when:** the user approved the final text and wants a new template.
- **Do not use when:** you only want a draft; there is none, so show the text to the user first.
- **Returns:** {id, status: PENDING, category}. The template shows in templates_list after the next sync, about a minute later.
- **Common errors:** "Hub rejected this operation: <Meta reason>" for invalid components; "Not permitted" without template write access.
- **Arguments:** `channel`, `name`, `language`, `category`, `parameter_format`?, `components`

### `templates_delete` (S)

Delete a template from Meta. Without id every language of that name is deleted.

- **Use when:** the user explicitly asked to delete this template.
- **Do not use when:** a running campaign uses it.
- **Returns:** Meta's delete result.
- **Common errors:** "arguments.confirm must be true"; "Hub rejected this operation".
- **Arguments:** `channel`, `name`, `id`?, `confirm`

### `templates_list` (R)

List WhatsApp templates with their Meta approval status, quality and rejection reason.

- **Use when:** choosing a template to send, or checking if a submitted template was approved.
- **Do not use when:** you need a chat; templates are not messages.
- **Returns:** {data: [{id, name, language, category, status, quality_score, rejected_reason, components}], sync: {synced_at, templates (count of the last sync), syncing}}. A list older than a minute starts a background sync.
- **Common errors:** "Not permitted" without a Relay role.
- **Arguments:** `channel`?, `status`?

### `templates_media_upload` (W)

Upload a header image, video or document for a template or template send. Requests up to 7 MB.

- **Use when:** a template has a media header.
- **Do not use when:** the file is reachable by HTTPS; chat_send_template takes header_media_url.
- **Returns:** {id: media handle for the header component}.
- **Common errors:** "This file type is not accepted for this <kind> header"; "The file must be at most <size>".
- **Arguments:** `channel`, `media_type`, `filename`, `content_base64`

### `templates_update` (S)

Change the components of an existing template. Meta reviews it again.

- **Use when:** the user wants to fix a rejected or old template.
- **Do not use when:** the template is new; use templates_create.
- **Returns:** Meta's update result.
- **Common errors:** "Hub rejected this operation: <Meta reason>"; Meta limits how often an approved template can change.
- **Arguments:** `channel`, `id`, `components`, `category`?

### `tickets_create` (W)

Create a ticket from 1-50 readable messages of one business scope.

- **Use when:** a customer request needs follow-up by the team.
- **Do not use when:** a ticket for these messages exists; check tickets_list.
- **Returns:** {name, ticket_status}.
- **Common errors:** "Messages must be a list of 1-50 references"; messages of different business records.
- **Arguments:** `subject`, `messages`, `brief`?, `ticket_type`?

### `tickets_list` (R)

List tickets, newest first, 30 per page.

- **Use when:** the user asks for open, own or matching support tickets.
- **Do not use when:** you know the ticket id; use tickets_read.
- **Returns:** {items: tickets, next: {after} or null}.
- **Common errors:** "Invalid ticket search"; "Not permitted" without a Relay role.
- **Arguments:** `query`?, `ticket_status`?, `mine`?, `after`?

### `tickets_read` (R)

Read one ticket with its linked messages and a page of its transcript.

- **Use when:** you work on a ticket or need its history.
- **Do not use when:** you only need the list; use tickets_list.
- **Returns:** {ticket: the ticket, transcript: {items, next}}.
- **Common errors:** "Not found" or "Not permitted" for a ticket outside the user's scope.
- **Arguments:** `name`, `after`?

### `tickets_update` (W)

Change a ticket: set status, assign to a user, claim it from AI, close it, or add an internal comment.

- **Use when:** the user asks to move, hand over, take or close a ticket.
- **Do not use when:** you want to message the customer; use chat_send_text.
- **Returns:** the updated ticket fields.
- **Common errors:** value is required for status (a status name), assign (a user email) and comment (text); "Not permitted" when assigning without the manager role.
- **Arguments:** `name`, `action`, `value`?
